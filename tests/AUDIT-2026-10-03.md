# Salon Modern audit — 3 October 2026

## Verified fix and release

v104 / commit 4c5c3c5 is live. The Web Push settings installer inserted a menu button before a nested drawer separator using the wrong parent. The resulting `NotFoundError` interrupted `enterApp`, prevented pending reminder routing, and was misleadingly reported by the session loader as a connection problem.

The actual application shell reproduced the failure before the fix. Using the separator's actual parent eliminates it. The local cold-open fixture now invokes the real wrapped `enterApp` and observes one WhatsApp URL attempt without a page error. This does not prove Android launched WhatsApp.

The preceding v101–v103 work covers deferred authentication bootstrap, stale update-banner dismissal, removal of the retired startup dashboard, robust push payload handling, and retaining unresolved notification navigation for retry. These are separate from intermittent Android push visibility.

## Remaining verification and findings

- Android closed-app system push was confirmed visible by the user in a controlled test. Intermittently missing real reminders are not established as fixed: provider `sent` is acceptance, not device display.
- Reminder timing in the supplied incident was correct; cron was not rewritten. There is insufficient device/SW receipt evidence to identify the cause of that missed Android notification.
- Physical v104 reminder-to-WhatsApp and ready-message test is pending. Browser fixtures confirm only routing logic/URL preparation.
- Local SQL integration/concurrency scripts were not rerun: required PGlite/embedded PostgreSQL/pg dependencies are absent from the bundled runtime. Live schema inspection is not a substitute for concurrent database connection tests.
- Supabase advisories: btree_gist in public; leaked-password protection disabled; authenticated SECURITY DEFINER RPCs; policyless RLS-protected internal tables; six unindexed foreign keys; repeated RLS auth evaluation; redundant permissive policies; unused-index notices. RPC definitions were inspected. No permissions, extension placement or indexes were changed solely because of a lint. Policyless internal tables remain closed to normal client access.
- Existing client-read policy allows active salon users to read clients; tightening this would change current customer-selection behaviour and is not silently applied here.

Security references: [Supabase database linter](https://supabase.com/docs/guides/database/database-linter), [password protection](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).
